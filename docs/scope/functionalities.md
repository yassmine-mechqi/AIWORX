# 4. Fonctionnalités

## 4.1 Présentation

La plateforme AIWORX est composée de plusieurs domaines fonctionnels permettant de couvrir le cycle complet d'une prestation de services digitaux.

Les principales fonctionnalités sont organisées autour des domaines suivants :

* Identity ;
* Marketplace ;
* Contract ;
* Delivery ;
* Trust ;
* Finance ;
* Platform ;
* Website ;
* Back-office.

Chaque domaine regroupe des fonctionnalités spécifiques et doit respecter les règles d'accès correspondant aux rôles des utilisateurs.

---

## 4.2 Gestion des comptes et de l'identité

AIWORX doit permettre la gestion des comptes utilisateurs et des organisations.

Les fonctionnalités comprennent notamment :

* inscription ;
* authentification ;
* vérification de l'adresse e-mail ;
* gestion du profil ;
* gestion des organisations ;
* gestion des rôles ;
* gestion des permissions ;
* gestion des consentements ;
* gestion du statut du compte.

Les droits disponibles dépendent du rôle de l'utilisateur.

---

## 4.3 Gestion des organisations

La plateforme doit permettre de représenter les organisations utilisant AIWORX.

Les informations d'une organisation peuvent notamment comprendre :

* identité de l'organisation ;
* informations de l'entreprise ;
* coordonnées ;
* utilisateurs associés ;
* rôles ;
* statut ;
* préférences ;
* consentements.

Les accès aux informations de l'organisation doivent être contrôlés selon les permissions.

---

## 4.4 Gestion des prestataires

La plateforme doit permettre aux prestataires de créer et gérer leur profil professionnel.

Le profil peut notamment contenir :

* compétences ;
* catégories ;
* sous-catégories ;
* secteurs d'expérience ;
* portfolio ;
* références ;
* documents ;
* tests ;
* badges ;
* certifications ;
* score qualité ;
* niveau de vérification.

Les informations nécessaires à la qualification doivent être fournies avant la validation du prestataire.

---

## 4.5 Qualification et vérification des prestataires

AIWORX doit disposer d'un processus de qualification des prestataires.

Le processus peut comprendre :

* vérification de l'adresse e-mail ;
* collecte des informations d'identité ;
* collecte des informations légales ;
* vérification des informations professionnelles ;
* analyse du portfolio ;
* vérification des références ;
* tests de compétences ;
* validation par AIWORX.

Les principaux statuts sont :

* brouillon ;
* en vérification ;
* compléments requis ;
* test ;
* validé ;
* suspendu ;
* refusé.

Les documents et informations requis ainsi que leur fréquence de revalidation doivent pouvoir être configurés.

---

## 4.6 Création d'un besoin

L'entreprise cliente doit pouvoir créer un besoin.

Plusieurs modes de création sont prévus :

* formulaire guidé ;
* description libre ;
* ajout de fichiers ;
* questionnaire intelligent ;
* import d'un cahier des charges ;
* entretien avec un conseiller AIWORX.

Le besoin doit pouvoir contenir :

* contexte ;
* objectifs ;
* cible ;
* périmètre ;
* livrables ;
* contraintes ;
* budget ;
* calendrier ;
* critères d'acceptation ;
* dépendances ;
* exclusions ;
* confidentialité.

---

## 4.7 Qualification du besoin

AIWORX doit permettre de transformer un besoin initial en spécification structurée.

La qualification peut être réalisée avec :

* assistance IA ;
* conseiller AIWORX ;
* informations fournies par le client ;
* documents fournis ;
* questionnaire de qualification.

La qualification doit permettre d'identifier les informations manquantes et de demander les compléments nécessaires.

---

## 4.8 Spécification du besoin

La plateforme doit permettre de créer une spécification structurée du besoin.

La spécification doit être :

* versionnée ;
* modifiable selon les droits ;
* commentable ;
* validable ;
* conservée avec son historique.

Une version validée peut devenir la version contractuelle de référence.

Une modification importante après validation doit pouvoir être traitée selon le processus d'avenant prévu.

---

## 4.9 Matching des prestataires

AIWORX doit permettre d'identifier les prestataires correspondant au besoin.

Le matching peut prendre en compte notamment :

* compétence ;
* catégorie ;
* sous-catégorie ;
* secteur ;
* expérience ;
* qualité ;
* délais ;
* éligibilité.

Le système peut retourner :

* un score ;
* les raisons positives ;
* les risques ;
* les critères manquants.

Le conseiller AIWORX peut écarter ou ajouter un prestataire avec justification.

AIWORX recommande les prestataires ; la décision finale appartient au client.

---

## 4.10 Sourcing

Plusieurs mécanismes de sourcing sont prévus :

* publication ouverte contrôlée ;
* recommandation AIWORX ;
* recherche dans le catalogue ;
* attribution directe ;
* service prédéfini.

Les règles de publication, d'invitation et de sélection doivent respecter les permissions et les règles métier définies.

---

## 4.11 Gestion des offres

Un prestataire autorisé peut créer une offre.

Une offre commence à l'état brouillon et reste modifiable avant sa soumission.

Elle peut contenir :

* résumé ;
* compréhension du besoin ;
* méthodologie ;
* étapes ;
* livrables ;
* exclusions ;
* dépendances ;
* planning ;
* prix ;
* validité ;
* disponibilité ;
* références ;
* questions.

Les jalons d'une offre peuvent préciser :

* titre ;
* dates ;
* montant indicatif ;
* critères de livraison.

La somme des jalons doit être cohérente avec le prix de l'offre selon les règles définies.

Le système contrôle les champs obligatoires, le budget, les dates et les pièces nécessaires avant la soumission.

---

## 4.12 Versionnement des offres

Après soumission, une modification d'une offre doit créer une nouvelle version sans écraser la version précédente.

Les principaux statuts d'une offre comprennent :

* brouillon ;
* soumise ;
* clarification ;
* à reconfirmer ;
* présélectionnée ;
* négociation ;
* retenue ;
* refusée ;
* retirée ;
* expirée.

L'historique des versions doit être conservé.

---

## 4.13 Comparaison des offres

AIWORX doit fournir un comparateur permettant de structurer la comparaison des offres.

Les critères de comparaison peuvent comprendre :

* score ;
* expérience ;
* méthode ;
* livrables ;
* exclusions ;
* délai ;
* prix ;
* risques.

Les prix des offres concurrentes ne doivent pas être présentés aux prestataires.

Le client voit les offres qu'AIWORX autorise ou présélectionne.

L'analyse IA peut produire une synthèse basée sur les informations réellement présentes dans l'offre.

Le conseiller peut ajouter une recommandation ou identifier un point à clarifier.

Le choix final doit être confirmé par le client.

---

## 4.14 Sélection du prestataire

L'entreprise cliente sélectionne le prestataire retenu.

La sélection doit être enregistrée.

Elle déclenche la préparation de la contractualisation.

Les motifs de refus peuvent être enregistrés afin d'améliorer le matching, sans être automatiquement communiqués aux autres utilisateurs.

---

## 4.15 Contrats

La plateforme doit permettre de gérer le processus contractuel.

Les fonctionnalités comprennent notamment :

* préparation du contrat ;
* gestion des versions ;
* validation ;
* signature ;
* conservation du contrat signé ;
* traçabilité des modifications importantes.

Le contrat doit permettre de formaliser les engagements liés à la prestation.

---

## 4.16 Signature électronique

La plateforme doit pouvoir intégrer un service de signature électronique externe.

L'intégration doit permettre de gérer :

* l'envoi du document ;
* le suivi de la signature ;
* le statut de signature ;
* la récupération du document signé ;
* la conservation du document ;
* la traçabilité de l'opération.

Le fournisseur de signature définitif reste un paramètre à confirmer.

---

## 4.17 Paiements et financement

AIWORX doit permettre de gérer les opérations financières liées aux missions.

Les fonctionnalités comprennent notamment :

* financement ;
* paiement ;
* suivi des transactions ;
* commissions ;
* frais ;
* remboursements ;
* reversements ;
* suivi des statuts financiers.

Les transactions doivent conserver une référence externe lorsque celle-ci existe.

Les opérations financières doivent être conçues de manière idempotente afin d'éviter les doubles traitements.

---

## 4.18 Gestion des missions

Après contractualisation et financement selon les conditions applicables, la prestation devient une mission.

La plateforme doit permettre de gérer :

* mission ;
* parties ;
* dates ;
* montant ;
* statut ;
* règles applicables ;
* jalons ;
* livrables ;
* contrôles ;
* validations.

---

## 4.19 Gestion des jalons

Une mission peut être divisée en plusieurs jalons.

Chaque jalon peut contenir :

* titre ;
* objectif ;
* date de début ;
* date d'échéance ;
* montant ;
* critères de livraison ;
* statut ;
* livrables associés.

Les principaux états peuvent comprendre :

* en attente ;
* soumis ;
* validé ;
* correction requise.

Les délais et règles de relance peuvent être configurés.

---

## 4.20 Gestion des livrables

Le prestataire doit pouvoir déposer les livrables associés à une mission ou à un jalon.

La plateforme doit permettre :

* dépôt de fichiers ;
* versionnement ;
* description ;
* association au jalon ;
* contrôle ;
* demande de correction ;
* nouvelle soumission ;
* validation.

Les anciennes versions importantes doivent rester accessibles selon les règles de conservation.

---

## 4.21 Contrôle qualité

Le contrôle qualité permet de vérifier la conformité d'un livrable avec les critères définis.

Le processus comprend notamment :

* sélection de la grille qualité ;
* vérification des critères ;
* ajout de preuves ;
* ajout de commentaires ;
* identification des non-conformités ;
* demande de correction ;
* contrôle de la nouvelle version.

Chaque critère peut recevoir un résultat tel que :

* conforme ;
* non conforme ;
* non applicable.

---

## 4.22 Validation client

Après le contrôle qualité AIWORX, le client peut intervenir dans la validation.

Le client peut :

* accepter le livrable ;
* refuser le livrable lorsque les critères contractuels ne sont pas respectés ;
* fournir le motif du refus ;
* demander une correction ;
* valider la version corrigée.

Le processus doit conserver les décisions et leur historique.

---

## 4.23 Validation finale

La validation finale permet de clôturer le processus de réalisation lorsque les conditions prévues sont satisfaites.

Elle constitue une étape importante avant le reversement final lorsque celui-ci dépend de cette validation.

La validation finale doit être traçable.

---

## 4.24 Reversements

AIWORX doit permettre de gérer les reversements dus au prestataire.

Les principaux statuts sont :

* non éligible ;
* retenu ;
* éligible ;
* approuvé ;
* en traitement ;
* payé ;
* échoué ;
* retourné.

Le reversement est lié aux conditions de validation prévues pour la mission.

---

## 4.25 Messagerie

La plateforme doit proposer une messagerie interne.

Les espaces de communication prévus comprennent notamment :

* avant-vente ;
* mission ;
* qualité ;
* finance ;
* litige.

Les messages peuvent être associés au contexte métier concerné.

Les pièces jointes doivent respecter les règles de sécurité et de contrôle des fichiers.

---

## 4.26 Protection contre le contournement

La plateforme peut contrôler les messages avant leur envoi afin de détecter certaines coordonnées ou tentatives de sortie du processus.

Les éléments concernés peuvent comprendre :

* adresse e-mail ;
* numéro de téléphone ;
* lien de réunion ;
* autres coordonnées détectées.

Les tentatives de contournement peuvent être enregistrées et déclencher les mécanismes prévus par les règles de la plateforme.

---

## 4.27 Notifications

AIWORX doit gérer les notifications associées aux événements importants.

Les canaux prévus comprennent :

* plateforme ;
* e-mail ;
* WhatsApp pour certaines notifications importantes.

Les événements pouvant déclencher des notifications comprennent notamment :

* signature ;
* paiement ;
* échéance ;
* retard ;
* livrable ;
* correction ;
* validation ;
* litige ;
* suspension ;
* reversement.

Les notifications critiques ne doivent pas pouvoir être désactivées.

Les relances doivent être dédupliquées et ne doivent pas être envoyées après résolution de l'événement.

---

## 4.28 Gestion des fichiers

La plateforme doit permettre la gestion sécurisée des fichiers associés aux utilisateurs, besoins, offres, contrats, missions et livrables.

Les fonctionnalités comprennent notamment :

* téléchargement ;
* stockage ;
* versionnement ;
* contrôle des formats ;
* contrôle de taille ;
* contrôle antivirus ;
* accès sécurisé ;
* URLs temporaires ;
* conservation selon les règles définies.

---

## 4.29 Gestion des litiges

AIWORX doit permettre de gérer les situations conflictuelles entre les parties.

Les fonctionnalités peuvent comprendre :

* déclaration d'un litige ;
* consultation des informations du dossier ;
* collecte des preuves ;
* intervention AIWORX ;
* médiation ;
* décision ;
* résolution ;
* traçabilité.

Les seuils et décideurs associés aux niveaux de litige doivent rester configurables.

---

## 4.30 Pénalités et sanctions

La plateforme doit pouvoir gérer les règles de pénalité prévues.

Ces règles peuvent concerner notamment :

* retard ;
* non-respect des engagements ;
* non-conformité ;
* tentative de contournement ;
* abandon de mission.

Les grilles et niveaux de pénalité doivent pouvoir être configurés.

---

## 4.31 Évaluation

Après la réalisation de la prestation, le client peut évaluer la prestation et le prestataire.

Les informations d'évaluation peuvent être utilisées pour :

* améliorer le suivi de la qualité ;
* contribuer au score du prestataire ;
* améliorer le matching ;
* suivre la satisfaction.

Les règles de visibilité des évaluations doivent respecter les paramètres définis par AIWORX.

---

## 4.32 Intelligence artificielle

Les fonctionnalités IA identifiées comprennent notamment :

### Qualification

L'IA peut assister :

* la compréhension du besoin ;
* la structuration ;
* l'identification des informations manquantes ;
* la génération de questions.

### Matching

L'IA peut contribuer à :

* l'analyse de compatibilité ;
* la génération d'un score ;
* l'explication des critères ;
* l'identification des risques.

### Analyse des offres

L'IA peut produire :

* synthèse ;
* comparaison ;
* identification des points forts ;
* identification des risques ;
* identification des éléments à clarifier.

### Contrôle qualité

L'IA peut assister certaines opérations de contrôle selon les fonctionnalités prévues.

Les résultats IA doivent rester traçables et ne doivent pas inventer d'informations absentes des données disponibles.

---

Le Back-office doit permettre aux équipes AIWORX de superviser la plateforme.

Les fonctionnalités comprennent notamment :

* recherche globale ;
* gestion des utilisateurs ;
* gestion des organisations ;
* gestion des prestataires ;
* files de vérification ;
* suivi des besoins ;
* suivi des offres ;
* suivi des risques ;
* suivi qualité ;
* gestion des litiges ;
* gestion des paiements ;
* gestion des alertes ;
* consultation du journal d'audit ;
* vue 360° d'un dossier.

Les actions administratives sensibles doivent nécessiter une permission appropriée et, lorsque prévu, un motif obligatoire.

## 4.35 Audit et traçabilité

Les actions importantes doivent être enregistrées dans un journal d'audit.

Les informations enregistrées peuvent comprendre :

* utilisateur ;
* rôle ;
* organisation ;
* action ;
* objet concerné ;
* état avant ;
* état après ;
* motif ;
* date ;
* informations techniques ;
* identifiant de corrélation.

L'accès au journal doit être limité aux rôles autorisés.

---

## 4.36 Priorisation des fonctionnalités

Le cahier des charges définit trois niveaux de priorité.

### P0 — Indispensable

Les fonctionnalités essentielles comprennent notamment :

* comptes ;
* rôles ;
* vérification ;
* besoins ;
* offres ;
* sélection ;
* contrats ;
* paiement ;
* missions ;
* jalons ;
* fichiers ;
* qualité ;
* messagerie ;
* audit ;
* Back-office.

### P1 — Lancement complet

Les fonctionnalités comprennent notamment :

* matching avancé ;
* IA de qualification ;
* comparaison ;
* notifications WhatsApp ;
* scoring ;
* litiges ;
* pénalités ;
* tableaux de bord.

### P2 — Optimisation

Les fonctionnalités comprennent notamment :

* IA qualité enrichie ;
* analytics avancés ;
* automatisations supplémentaires ;
* catalogue fixe/configurable ;
* personnalisation.

Une fonctionnalité P1 ne doit pas retarder une exigence P0 concernant notamment la sécurité, la finance ou la traçabilité.

---

## 4.37 Résumé des fonctionnalités

Les fonctionnalités AIWORX couvrent donc l'ensemble du cycle :

```text
Identity
    ↓
Marketplace
    ↓
Qualification
    ↓
Matching
    ↓
Offres
    ↓
Sélection
    ↓
Contract
    ↓
Paiement
    ↓
Delivery
    ↓
Jalons
    ↓
Livrables
    ↓
Quality
    ↓
Validation
    ↓
Reversement
    ↓
Évaluation
```

Les fonctions transversales comprennent :

```text
Platform
├── Messaging
├── Notifications
├── Files
├── Audit
├── AI
└── Back-office
```

Cette organisation constitue la base pour définir les workflows détaillés, les règles métier, les API, l'architecture Backend et le modèle de données.
