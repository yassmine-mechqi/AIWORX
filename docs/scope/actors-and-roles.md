# 3. Acteurs et rôles

## 3.1 Présentation

AIWORX implique plusieurs catégories d'acteurs intervenant à différentes étapes du cycle de vie d'une prestation.

Chaque acteur dispose de responsabilités et de droits adaptés à son rôle.

Les principaux acteurs identifiés dans le cahier des charges sont :

* Entreprise cliente ;
* Prestataire individuel / agence ;
* Conseiller AIWORX ;
* Expert qualité AIWORX ;
* Administrateur financier.

La plateforme doit contrôler les accès et les actions disponibles selon le rôle de l'utilisateur.

---

## 3.2 Entreprise cliente

### 3.2.1 Présentation

L'entreprise cliente est l'organisation qui utilise AIWORX pour exprimer un besoin, rechercher un prestataire et faire réaliser une prestation de services digitaux.

Elle constitue l'une des parties principales du processus métier.

### 3.2.2 Responsabilités principales

L'entreprise cliente peut notamment :

* créer et gérer son compte ;
* fournir les informations relatives à son organisation ;
* créer un besoin ;
* décrire son besoin ;
* fournir les documents nécessaires ;
* répondre aux questions de qualification ;
* participer à l'entretien de qualification lorsqu'il est prévu ;
* valider la spécification du besoin ;
* consulter les prestataires proposés ;
* recevoir et consulter les offres ;
* comparer les offres ;
* demander des clarifications ;
* participer à la négociation ;
* sélectionner un prestataire ;
* valider les éléments contractuels ;
* signer le contrat ;
* financer la prestation ;
* suivre la mission ;
* suivre les jalons ;
* consulter les livrables ;
* participer au contrôle des livrables ;
* accepter ou refuser un livrable avec un motif lié aux critères contractuels ;
* participer à la validation finale ;
* effectuer une évaluation de la prestation.

### 3.2.3 Gestion du besoin

L'entreprise cliente peut commencer la création d'un besoin à travers plusieurs parcours :

* formulaire guidé ;
* description libre ;
* ajout de fichiers ;
* questionnaire intelligent ;
* import d'un cahier des charges existant ;
* entretien avec un conseiller AIWORX.

Le besoin doit pouvoir être transformé en un dossier structuré comprenant notamment :

* contexte ;
* objectifs ;
* cible ;
* périmètre ;
* livrables ;
* contraintes ;
* budget ;
* calendrier ;
* critères d'acceptation ;
* dépendances ;
* exclusions ;
* niveau de confidentialité.

### 3.2.4 Validation

L'entreprise cliente intervient dans plusieurs étapes de validation.

Elle doit notamment :

* valider la spécification du besoin ;
* valider les éléments contractuels ;
* signer le contrat ;
* participer à la validation des livrables ;
* réaliser la validation finale lorsque celle-ci lui revient ;
* fournir une évaluation après la prestation.

---

## 3.3 Prestataire individuel / agence

### 3.3.1 Présentation

Le prestataire est un professionnel ou une agence proposant ses services à travers AIWORX.

Le prestataire doit être vérifié avant d'accéder pleinement aux opportunités de la plateforme.

### 3.3.2 Responsabilités principales

Le prestataire peut notamment :

* créer son compte ;
* vérifier son adresse e-mail ;
* fournir ses informations d'identité ;
* fournir ses informations légales ;
* fournir ses informations professionnelles ;
* présenter ses compétences ;
* sélectionner ses catégories de services ;
* fournir son portfolio ;
* fournir ses références ;
* fournir les documents demandés ;
* effectuer les tests de compétences prévus ;
* suivre son processus de vérification ;
* recevoir des opportunités correspondant à son profil ;
* consulter les besoins auxquels il est autorisé à accéder ;
* poser des questions ;
* soumettre des offres ;
* modifier ou négocier les éléments de son offre lorsque le processus le permet ;
* suivre ses offres ;
* exécuter les missions obtenues ;
* gérer les jalons ;
* déposer les livrables ;
* fournir les fichiers, sources, accès ou documentations attendus ;
* effectuer les corrections demandées ;
* suivre la validation des livrables ;
* recevoir le reversement conformément aux conditions prévues.

### 3.3.3 Vérification du prestataire

Le processus de vérification peut comprendre :

* vérification de l'adresse e-mail ;
* vérification d'identité ;
* vérification des documents légaux ;
* vérification des informations professionnelles ;
* étude du portfolio ;
* étude des références ;
* tests de compétences ;
* validation manuelle par AIWORX.

Les états prévus pour le processus de qualification sont notamment :

* brouillon ;
* en vérification ;
* compléments requis ;
* test ;
* validé ;
* suspendu ;
* refusé.

### 3.3.4 Profil public

Une fois autorisé à être présenté sur la plateforme, le profil du prestataire peut contenir :

* présentation ;
* compétences ;
* catégories de services ;
* portfolio ;
* références ;
* secteurs d'expérience ;
* avis ;
* score qualité ;
* badges ;
* certifications ;
* niveau de vérification.

Les coordonnées directes du prestataire sont protégées avant l'étape autorisée afin de limiter le contournement de la plateforme.

### 3.3.5 Exécution des missions

Après sélection, contractualisation et satisfaction des conditions nécessaires au démarrage, le prestataire exécute la mission.

Il doit notamment :

* respecter le cahier des charges contractuel ;
* respecter les jalons ;
* déposer les livrables attendus ;
* répondre aux demandes de contrôle ;
* corriger les non-conformités ;
* fournir les éléments nécessaires à la livraison complète ;
* respecter les conditions de la mission.

---

## 3.4 Conseiller AIWORX

### 3.4.1 Présentation

Le conseiller AIWORX intervient comme acteur d'accompagnement et de supervision du processus.

Il intervient notamment dans la qualification des besoins, la sélection des prestataires, la négociation et le suivi des missions.

### 3.4.2 Responsabilités principales

Le conseiller peut notamment :

* accompagner l'entreprise dans la qualification du besoin ;
* réaliser ou participer à l'entretien de qualification ;
* analyser les informations fournies par le client ;
* enrichir et structurer le besoin ;
* modifier la spécification ;
* demander des compléments ;
* participer à la validation de la spécification ;
* recommander des prestataires ;
* effectuer ou superviser l'attribution d'un prestataire ;
* demander des clarifications aux prestataires ;
* accompagner la négociation ;
* superviser les échanges ;
* suivre les délais ;
* suivre les risques ;
* intervenir en cas de problème ;
* déclencher une médiation lorsque cela est nécessaire.

### 3.4.3 Intervention dans le sourcing

Le conseiller AIWORX peut intervenir dans les différents modes de sourcing prévus :

* publication ouverte contrôlée ;
* recommandation AIWORX ;
* recherche dans le catalogue ;
* attribution directe ;
* service prédéfini.

Dans le cas d'une recommandation AIWORX, le moteur peut proposer une sélection courte qui doit être validée par un conseiller.

### 3.4.4 Intervention dans la négociation

Le conseiller peut notamment :

* demander une clarification ;
* demander une révision ;
* accompagner les échanges ;
* vérifier que les éléments négociés restent cohérents avec le besoin ;
* superviser les changements importants.

Les décisions importantes doivent rester traçables.

---

## 3.5 Expert qualité AIWORX

### 3.5.1 Présentation

L'expert qualité AIWORX intervient dans le contrôle des livrables produits par le prestataire.

Il vérifie la conformité des livrables par rapport aux exigences contractuelles et aux critères définis.

### 3.5.2 Responsabilités principales

L'expert qualité peut notamment :

* recevoir un livrable à contrôler ;
* vérifier les éléments fournis ;
* appliquer la grille qualité correspondant à la catégorie ;
* vérifier les critères obligatoires ;
* identifier les non-conformités ;
* fournir des preuves et commentaires ;
* demander des corrections ;
* contrôler une nouvelle version ;
* valider le résultat du contrôle ;
* produire les éléments nécessaires au rapport qualité.

### 3.5.3 Indépendance du contrôle

Le contrôle qualité doit être réalisé par un expert compétent et sans conflit d'intérêts.

L'expert applique la grille correspondant au service concerné.

Chaque critère peut recevoir un résultat tel que :

* conforme ;
* non conforme ;
* non applicable.

Le contrôle doit être accompagné des preuves ou commentaires nécessaires.

### 3.5.4 Contrôle en deux étapes

Le processus prévoit deux niveaux de contrôle :

1. contrôle AIWORX ;
2. contrôle client.

Le contrôle AIWORX intervient avant la validation client.

L'expert qualité vérifie notamment :

* les critères contractuels ;
* les exigences du livrable ;
* les éléments obligatoires ;
* les preuves nécessaires ;
* la conformité générale.

---

## 3.6 Administrateur financier

### 3.6.1 Présentation

L'administrateur financier intervient dans la supervision des opérations financières liées aux prestations.

Il assure le suivi des encaissements, commissions, factures, remboursements autorisés et reversements.

### 3.6.2 Responsabilités principales

L'administrateur financier peut notamment :

* suivre les paiements ;
* suivre les encaissements ;
* suivre les transactions ;
* suivre les commissions ;
* suivre les factures ;
* suivre les remboursements autorisés ;
* suivre les reversements ;
* contrôler les statuts financiers ;
* identifier les opérations échouées ;
* traiter les situations nécessitant une intervention ;
* superviser les opérations financières importantes.

### 3.6.3 Suivi des paiements

Les transactions doivent permettre de conserver notamment :

* le type de transaction ;
* le montant ;
* la devise ;
* la partie concernée ;
* la mission ;
* le jalon éventuel ;
* la référence du fournisseur ;
* le statut.

Les statuts de paiement prévus comprennent notamment :

* initié ;
* action requise ;
* autorisé ;
* payé ;
* échoué ;
* annulé ;
* remboursé partiellement ;
* remboursé.

### 3.6.4 Suivi des reversements

Les reversements peuvent notamment avoir les statuts suivants :

* non éligible ;
* retenu ;
* éligible ;
* approuvé ;
* en traitement ;
* payé ;
* échoué ;
* retourné.

Par défaut, aucun reversement n'est effectué avant la validation finale de l'ensemble du projet, sauf exception contractuellement autorisée.

## 3.7 Relations entre les acteurs

Les acteurs collaborent tout au long du cycle de vie d'une prestation.

Le fonctionnement général peut être représenté ainsi :

```text
Entreprise cliente
        │
        │ Besoin
        ▼
Conseiller AIWORX
        │
        │ Qualification / accompagnement
        ▼
Matching / Sourcing
        │
        ▼
Prestataire
        │
        │ Offre
        ▼
Entreprise cliente
        │
        │ Sélection
        ▼
Contrat
        │
        ▼
Prestataire
        │
        │ Exécution / Livrables
        ▼
Expert qualité AIWORX
        │
        │ Contrôle
        ▼
Entreprise cliente
        │
        │ Validation
        ▼
Administrateur financier
        │
        │ Reversement
        ▼
Prestataire
```

## 3.9 Gestion des rôles et permissions

Les fonctionnalités accessibles à chaque acteur doivent être contrôlées par le système d'autorisation.

Un utilisateur ne doit pouvoir effectuer que les actions correspondant à son rôle et à son contexte d'accès.

Les permissions doivent notamment contrôler :

* l'accès aux informations ;
* l'accès aux documents ;
* la création et modification des besoins ;
* la consultation des offres ;
* la gestion des contrats ;
* la validation des livrables ;
* les opérations financières ;
* les actions administratives ;
* les actions de contrôle qualité ;
* les actions liées aux litiges.

Les actions sensibles doivent être protégées par des permissions appropriées et faire l'objet d'une traçabilité lorsqu'elles sont concernées par le journal d'audit.

---

## 3.10 Confidentialité entre les acteurs

Les informations accessibles aux acteurs doivent dépendre de l'étape du processus.

Avant la présélection ou l'étape autorisée :

* l'identité du client peut être masquée ;
* les prix des offres concurrentes sont masqués ;
* le contenu des offres concurrentes est masqué ;
* les documents sensibles peuvent nécessiter un engagement de confidentialité.

Les coordonnées directes du prestataire ne doivent pas être accessibles avant l'étape autorisée.

Les accès aux documents et informations sensibles doivent être contrôlés et les consultations importantes peuvent être journalisées.

---

## 3.11 Communication entre les acteurs

La plateforme fournit une messagerie interne permettant de gérer les communications liées au processus.

Les canaux prévus sont notamment :

* avant-vente ;
* mission ;
* qualité ;
* finance ;
* litige.

Dans la V1, les appels directs entre client et prestataire ne sont pas prévus.

Les tentatives de partage de coordonnées telles que :

* e-mail ;
* numéro de téléphone ;
* liens de réunion ;
* autres coordonnées détectées ;

peuvent être bloquées avant l'envoi afin de limiter le contournement de la plateforme.

Les tentatives de contournement doivent pouvoir être enregistrées et faire l'objet d'une alerte ou d'une sanction progressive selon les règles définies par AIWORX.

---

## 3.12 Actions nécessitant une intervention humaine

Certaines actions importantes du processus doivent conserver une intervention humaine.

Cela concerne notamment :

* la validation des prestataires ;
* certaines décisions de recommandation ;
* la supervision des négociations ;
* le contrôle qualité ;
* les décisions de pénalité ;
* le remplacement d'un prestataire ;
* les décisions liées aux litiges ;
* certaines opérations financières ;
* les actions administratives sensibles.

L'intelligence artificielle peut assister certains processus, mais les décisions nécessitant une validation humaine ne doivent pas être transformées en décisions automatiques irréversibles.

---

## 3.13 Traçabilité des actions des acteurs

Les actions importantes réalisées par les acteurs doivent pouvoir être tracées.

Le journal d'audit peut notamment enregistrer :

* l'acteur ;
* son rôle ;
* son organisation ;
* l'action réalisée ;
* l'objet concerné ;
* l'état avant l'action ;
* l'état après l'action ;
* le motif ;
* l'adresse technique ;
* la date ;
* l'identifiant de corrélation.

L'accès au journal d'audit est réservé aux rôles autorisés.

---

## 3.14 Synthèse des acteurs

AIWORX repose donc sur cinq catégories principales d'acteurs :

```text
                    AIWORX
                       │
        ┌──────────────┼──────────────┐
        │              │              │
   Entreprise      Prestataire     Équipe AIWORX
    cliente        individuel /         │
       │             agence             │
       │                                │
       │                     ┌──────────┼──────────┐
       │                     │          │          │
       │                Conseiller   Expert     Admin.
       │                AIWORX      qualité    financier
       │
       └──────────── Cycle de prestation ────────────┘
```

Chaque acteur intervient à des étapes différentes du processus et dispose de permissions adaptées à ses responsabilités.

Cette répartition constitue la base de la définition des rôles, permissions, workflows, règles métier et structures de données de la plateforme AIWORX.
