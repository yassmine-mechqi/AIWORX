# 2. Périmètre du projet

## 2.1 Présentation

AIWORX est une plateforme numérique de services destinée initialement au marché marocain B2B.

La plateforme a pour objectif de mettre en relation des entreprises clientes avec des prestataires de services vérifiés, tout en assurant un accompagnement, une qualification des besoins, un contrôle de la qualité, une gestion contractuelle et un suivi financier.

Le périmètre initial du projet comprend trois composantes principales :

* un Website public ;
* une Marketplace permettant la gestion des besoins, des prestataires et des projets ;
* un Back-office permettant aux équipes AIWORX de gérer, contrôler et administrer la plateforme.

Le projet est prévu sur un horizon initial de 4 à 6 mois.

---

## 2.2 Périmètre fonctionnel

Le périmètre fonctionnel couvre le cycle complet d'une prestation de service, depuis l'inscription de l'utilisateur jusqu'à l'évaluation finale de la mission.

Le cycle principal est le suivant :

1. Inscription et création du compte.
2. Création du besoin.
3. Qualification du besoin.
4. Matching entre le besoin et les prestataires.
5. Création et soumission des offres.
6. Comparaison et négociation des offres.
7. Sélection du prestataire.
8. Contractualisation et signature.
9. Financement de la prestation.
10. Démarrage et exécution de la mission.
11. Gestion des jalons.
12. Contrôle de la qualité des livrables.
13. Gestion des corrections.
14. Validation finale.
15. Reversement au prestataire.
16. Évaluation de la prestation.

---

## 2.3 Website public

Le Website constitue la partie publique de la plateforme.

Il permet notamment aux visiteurs de découvrir AIWORX, les services proposés et les prestataires présents sur la plateforme.

Les principales pages publiques identifiées sont :

* Accueil ;
* Services ;
* Prestataires ;
* Publier un besoin ;
* Réalisations ;
* Devenir prestataire.

Le Website doit être disponible en français et en anglais.

---

## 2.4 Marketplace

La Marketplace constitue le cœur fonctionnel de la plateforme.

Elle permet aux entreprises clientes de publier et gérer leurs besoins et aux prestataires de présenter leurs compétences, leurs références et leurs offres.

Les principales fonctionnalités couvertes sont :

### Gestion des utilisateurs

* création de compte ;
* authentification ;
* vérification de l'adresse e-mail ;
* gestion du profil ;
* gestion des rôles et permissions.

### Gestion des organisations

La plateforme permet de représenter les entreprises clientes et les structures professionnelles utilisant AIWORX.

Les informations nécessaires à l'identification et à la gestion de l'organisation sont prises en compte dans le processus d'inscription et de vérification.

### Gestion des prestataires

Le parcours prestataire comprend notamment :

* présentation du prestataire ;
* compétences ;
* catégories de services ;
* portfolio ;
* références ;
* secteurs d'activité ;
* avis AIWORX ;
* score qualité ;
* badges et certifications ;
* niveau de vérification.

Les coordonnées directes du prestataire ne sont pas nécessairement accessibles avant l'étape autorisée du processus.

### Qualification des prestataires

Le processus de qualification peut comprendre :

* vérification de l'adresse e-mail ;
* informations d'identité ;
* informations légales ;
* informations professionnelles ;
* portfolio et références ;
* tests de compétences ;
* validation manuelle par AIWORX.

Le prestataire peut passer par plusieurs états de traitement, notamment :

* brouillon ;
* en vérification ;
* compléments requis ;
* test ;
* validé ;
* suspendu ;
* refusé.

### Gestion des besoins

Une entreprise cliente peut créer un besoin à partir de plusieurs mécanismes :

* formulaire guidé ;
* description libre ;
* ajout de fichiers ;
* questionnaire intelligent ;
* import d'un cahier des charges existant ;
* entretien avec un conseiller AIWORX.

Le besoin qualifié doit notamment permettre de définir :

* contexte ;
* objectifs ;
* cible ;
* périmètre ;
* livrables ;
* contraintes ;
* budget ;
* délai ;
* critères d'acceptation ;
* dépendances ;
* exclusions ;
* confidentialité.

### Spécification du besoin

AIWORX permet d'assister la transformation du besoin en une spécification structurée.

Cette spécification peut être :

* structurée avec l'aide de l'IA ;
* modifiée par un conseiller AIWORX ;
* commentée ;
* versionnée ;
* validée par le client.

Une version validée peut devenir la version contractuelle de référence.

Les modifications importantes peuvent nécessiter un avenant avec prise en compte de leur impact sur le prix et le délai.

### Matching

La plateforme permet d'identifier des prestataires correspondant au besoin qualifié.

Le matching peut notamment prendre en compte les informations relatives :

* aux compétences ;
* aux catégories ;
* aux secteurs ;
* aux références ;
* aux qualifications ;
* au niveau de vérification ;
* aux besoins du projet.

### Consultation et sourcing

Plusieurs modes de sourcing sont prévus :

* publication ouverte contrôlée ;
* recommandation par AIWORX ;
* recherche dans le catalogue ;
* attribution directe ;
* service prédéfini.

### Offres

Les prestataires invités ou autorisés peuvent soumettre une offre.

Une offre peut contenir notamment :

* compréhension du besoin ;
* méthodologie ;
* étapes ;
* livrables ;
* critères d'acceptation ;
* références pertinentes ;
* questions ;
* prix final ;
* délai ;
* jalons ;
* dépendances ;
* conditions ;
* durée de validité ;
* disponibilité pour le démarrage.

### Comparaison et négociation

La plateforme permet de comparer les offres sur une base structurée.

Les éléments de comparaison comprennent notamment :

* compréhension du besoin ;
* méthodologie ;
* livrables ;
* expérience ;
* prix ;
* délai ;
* risques ;
* score.

L'IA peut assister l'analyse et la synthèse des offres.

Le conseiller AIWORX peut également intervenir pour demander des clarifications ou accompagner les échanges.

### Sélection

L'entreprise cliente sélectionne le prestataire avec lequel elle souhaite poursuivre le processus.

La sélection déclenche les étapes suivantes du processus contractuel.

---

## 2.5 Contractualisation

Après la sélection du prestataire, la plateforme prend en charge les étapes liées à la contractualisation.

Le processus comprend notamment :

* préparation du contrat ;
* validation des éléments contractuels ;
* gestion des versions ;
* signature ;
* conservation de la version signée.

La version contractuelle doit permettre de conserver la référence du besoin, des engagements et des conditions convenues entre les parties.

---

## 2.6 Financement et paiements

La plateforme intègre un processus financier associé à la prestation.

Le financement intervient dans le cycle entre la contractualisation et l'exécution de la mission.

Le processus financier doit permettre notamment de gérer :

* le paiement ;
* le suivi des opérations financières ;
* le reversement au prestataire ;
* les éventuels remboursements ;
* les situations nécessitant un blocage ou une intervention.

Les opérations financières importantes doivent être traçables.

Les mécanismes techniques précis du prestataire de paiement et les modalités détaillées d'intégration devront être définis dans la conception technique.

---

## 2.7 Exécution de la mission

Après contractualisation et validation des conditions nécessaires au démarrage, la mission peut commencer.

La gestion de la mission couvre notamment :

* le démarrage ;
* les jalons ;
* les livrables ;
* les versions des livrables ;
* le contrôle qualité ;
* les demandes de correction ;
* la validation finale.

---

## 2.8 Jalons

Une mission peut être organisée autour de plusieurs jalons.

Chaque jalon permet de structurer l'avancement de la prestation et de suivre les éléments attendus.

Les informations associées à un jalon peuvent notamment comprendre :

* objectif ;
* livrables attendus ;
* délai ;
* état ;
* validation ;
* éventuelles corrections.

---

## 2.9 Livrables et contrôle qualité

Les livrables sont soumis au processus de contrôle prévu par la plateforme.

Le contrôle qualité permet de vérifier la conformité des livrables par rapport aux éléments attendus.

En cas de non-conformité, une demande de correction peut être créée.

Le prestataire peut alors soumettre une nouvelle version du livrable.

Les différentes versions doivent être conservées afin d'assurer la traçabilité du processus.

---

## 2.10 Validation finale

À la fin de la mission, les livrables sont soumis à la validation finale.

La validation finale permet de clôturer le processus de réalisation lorsque les conditions prévues sont satisfaites.

Elle constitue également une étape importante avant le reversement final lorsque celui-ci dépend de cette validation.

---

## 2.11 Reversement

Après validation des conditions nécessaires, le processus de reversement au prestataire peut être exécuté.

Les opérations de reversement doivent être enregistrées et traçables.

Les éventuels blocages ou anomalies doivent pouvoir être identifiés et traités par les personnes autorisées.

---

## 2.12 Évaluation

Après la réalisation de la prestation, une évaluation peut être réalisée.

Cette étape permet notamment de recueillir des informations sur :

* la qualité de la prestation ;
* le respect des engagements ;
* l'expérience avec le prestataire ;
* la satisfaction du client.

Les informations issues des évaluations peuvent contribuer au suivi de la qualité des prestataires.

---

## 2.13 Back-office AIWORX

Le Back-office est destiné aux équipes internes d'AIWORX.

Il permet de superviser et administrer les différentes activités de la plateforme.

Les fonctions concernées comprennent notamment :

* gestion des utilisateurs ;
* gestion des organisations ;
* validation des prestataires ;
* contrôle des qualifications ;
* supervision des besoins ;
* suivi des projets ;
* contrôle qualité ;
* gestion financière ;
* gestion des litiges ;
* gestion des notifications ;
* consultation des journaux d'audit ;
* administration de la plateforme.

Les permissions du Back-office doivent dépendre du rôle de l'utilisateur interne.

---

## 2.14 Messagerie et notifications

La plateforme doit permettre la circulation des informations nécessaires au bon déroulement des processus.

Les mécanismes de communication peuvent notamment couvrir :

* notifications ;
* échanges liés aux besoins ;
* échanges avec les prestataires ;
* demandes de clarification ;
* informations relatives aux jalons ;
* informations relatives aux livrables ;
* événements importants du processus.

Les actions importantes doivent pouvoir être tracées.

---

## 2.15 Intelligence artificielle

L'IA intervient comme composant d'assistance dans plusieurs processus de la plateforme.

Les principaux usages identifiés sont :

* qualification du besoin ;
* structuration de la spécification ;
* matching ;
* analyse des offres ;
* synthèse des informations ;
* assistance au contrôle qualité.

L'IA intervient comme outil d'assistance et ne remplace pas les étapes de validation humaine prévues dans les processus AIWORX.

---

## 2.16 Sécurité et traçabilité

La sécurité constitue un élément transversal du périmètre.

La plateforme doit notamment prendre en compte :

* authentification ;
* autorisation selon les rôles ;
* protection des données ;
* confidentialité des informations ;
* contrôle des accès aux fichiers ;
* traçabilité des actions importantes ;
* journalisation des événements ;
* protection des opérations financières.

Les exigences techniques détaillées seront précisées dans la documentation d'architecture et de sécurité.

---

## 2.17 Périmètre géographique et commercial

Le marché initial ciblé par AIWORX est le Maroc et le contexte commercial initial est B2B.

La plateforme est donc conçue initialement pour répondre aux besoins :

* des entreprises clientes ;
* des prestataires individuels ;
* des agences ;
* des équipes internes AIWORX.

Une extension à d'autres marchés ou à d'autres contextes pourra être étudiée ultérieurement, mais elle ne constitue pas le périmètre initial documenté.
